Unit I

Introduction to Internet Technologies

Internet technologies encompass the collection of standards, hardware systems, and software protocols that facilitate global computing interconnections and information exchange.

1. The TCP/IP Protocol Suite

The Transmission Control Protocol/Internet Protocol (TCP/IP) model forms the bedrock of internet communications, organized across four functional layers:

  • Application Layer: Interfaces directly with end-user software (e.g., HTTP, HTTPS, FTP, DNS, SMTP).
  • Transport Layer: Establishes host-to-host data transfer. TCP provides connection-oriented, reliable, sequenced transmission with flow/congestion control, whereas UDP provides lightweight, connectionless datagram delivery.
  • Internet Layer: Manages logical addressing and packet routing across networks using IPv4 and IPv6.
  • Link Layer (Network Access): Deals with physical hardware addresses (MAC), ethernet frames, and data transmission over physical media.

2. Hypertext Transfer Protocol (HTTP / HTTPS)

HTTP is a stateless, application-level request-response protocol operating over TCP port 80 (or port 443 with TLS encryption in HTTPS).

HTTP Request Structure

  • Request Line: Method (GET, POST, etc.), URI, and HTTP Version.
  • Headers: Metadata like Host, User-Agent, Accept, Authorization.
  • Body: Payload data (applicable in POST/PUT requests).

HTTP Status Codes

  • 200 OK: Request succeeded.
  • 301 / 302: Permanent or temporary redirection.
  • 400 Bad Request: Malformed client syntax.
  • 404 Not Found: Resource does not exist.
  • 500 Internal Server Error: Unhandled server failure.

3. Domain Name System (DNS) Mechanics

DNS translates human-readable hostnames (e.g., portal.university.edu) into routable IP addresses (e.g., 192.0.2.1). The resolution workflow progresses hierarchically:

  1. Local browser cache & OS resolver query.
  2. Recursive DNS Resolver (ISP or enterprise resolver).
  3. Root Nameserver (directs to TLD server like .edu).
  4. Top-Level Domain (TLD) Nameserver (directs to authoritative name server).
  5. Authoritative Nameserver (returns matching A/AAAA IP record).

4. Client-Side vs. Server-Side Scripting

Criteria Client-Side Scripting (e.g., JavaScript) Server-Side Scripting (e.g., PHP)
Execution Context Client web browser (Chrome, Firefox, Safari). Web server runtime (Apache/PHP-FPM engine).
Source Code Visibility Viewable by inspecting page source or DevTools. Hidden from user; browser only receives emitted HTML/JSON.
Primary Purpose UI dynamism, DOM manipulation, client-side validation. Business logic, database interaction, session auth.
Database Access Cannot safely connect directly to backend databases. Direct, credentialed connectivity to SQL/NoSQL storage.
